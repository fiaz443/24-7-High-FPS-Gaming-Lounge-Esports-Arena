****🎮 High-Performance Gaming Lounge & Esports Arena Network****

Project 1.4 | Cisco Packet Tracer | CCNA Networking Portfolio

**Project overview**

This project simulates a small-scale esports gaming lounge network using Cisco Packet Tracer. The network is designed to separate competitive gaming traffic from casual gaming and streaming activities, provide inter-VLAN connectivity, and prioritize tournament traffic on the WAN uplink during periods of network congestion.

The design follows a practical networking scenario in which an esports arena operations manager requires improved traffic management, network segmentation, and low-latency connectivity for competitive gaming.

**🎯 Business Requirements**

Protect tournament PCs from unnecessary traffic generated by casual gaming and streaming users.

Separate tournament, casual gaming, local game server, and streaming devices into dedicated VLANs.

Enable communication between VLANs through router-on-a-stick inter-VLAN routing.

Automatically assign IP addresses to gaming clients using DHCP.

Prioritize tournament traffic on the WAN interface using class-based QoS.

Provide outbound internet connectivity through NAT/PAT.

Verify network operation using connectivity tests and Cisco IOS show commands.

⚙️ Technologies Implemented

1. VLAN Segmentation

Four VLANs separate the major operational areas of the gaming lounge:

VLAN 50: Competitive esports tournament systems.

VLAN 60: Casual gaming clients.

VLAN 70: Local dedicated game server.

VLAN 80: Streaming and production workstation.

VLANs create separate Layer 2 broadcast domains and provide a foundation for applying inter-VLAN security policies.

2. Router-on-a-Stick Inter-VLAN Routing

The Cisco 2911 router uses 802.1Q subinterfaces on GigabitEthernet0/0 to route traffic between the four VLANs.

The physical switch-to-router connection operates as an 802.1Q trunk, carrying traffic for VLANs 50, 60, 70, and 80.

Important: Devices in different VLANs must use a router or Layer 3 switch to communicate. Therefore, traffic from VLAN 50 to the game server in VLAN 70 requires inter-VLAN routing in this design.

3. DHCP Address Assignment

Separate DHCP pools provide IP addresses and default gateways for tournament and casual gaming clients.

Example configuration:

ip dhcp pool ESPORTS_POOL
 network 192.168.50.0 255.255.255.0
 default-router 192.168.50.1
 dns-server 1.1.1.1

ip dhcp pool CASUAL_POOL
 network 192.168.60.0 255.255.255.0
 default-router 192.168.60.1
 dns-server 1.1.1.1

DHCP pools for VLANs 70 and 80 can be added if automatic addressing is required for those devices. Alternatively, assign static IP addresses to the server and production workstation.

4. Quality of Service (QoS)

Class-Based Weighted Fair Queuing (CBWFQ) and a priority queue are used to demonstrate preferential handling of tournament traffic on the WAN egress interface.

The intended policy:

Match traffic sourced from 192.168.50.0/24.

Place matching packets into the esports traffic class.

Configure a priority bandwidth allocation.

Provide fair queuing for other traffic where supported.

QoS is especially useful when the WAN link is congested. It cannot eliminate latency caused by remote servers, internet routing, physical distance, or upstream congestion.

Traffic marking note: The source-based ACL classifies traffic but does not automatically mark packets as DSCP CS4 or AF41. Explicit DSCP marking must be configured separately if required. These DSCP values should be selected according to the application's traffic and the network's QoS policy.

5. NAT/PAT

Network Address Translation with overload translates multiple internal client addresses to the router's WAN interface address.

The intended inside networks include VLANs 50, 60, and 80. Include VLAN 70 only if the local game server also requires outbound internet access.

Example:

ip access-list standard NAT_GAMERS
 permit 192.168.50.0 0.0.0.255
 permit 192.168.60.0 0.0.0.255
 permit 192.168.80.0 0.0.0.255

ip nat inside source list NAT_GAMERS interface GigabitEthernet0/1 overload

Apply ip nat inside to the required inside interfaces and ip nat outside to the WAN interface.

The ISP-side topology must provide a valid routed path and return traffic for NAT to work.

Connectivity Tests

Test connectivity between VLANs where routing is permitted.

Ping the local game server from an esports PC.

Test the simulated external server after configuring the ISP-side routing.

Generate traffic and inspect the QoS policy counters.

Generate outbound traffic and verify NAT translations.

Expected results: Correct VLAN membership, valid DHCP leases, reachable gateways, successful permitted connectivity tests, and increasing QoS counters when matching traffic traverses the policy.

Actual latency, packet loss, and QoS behavior depend on the Packet Tracer version, device support, traffic conditions, and topology configuration.

⚠️ Packet Tracer Implementation Notes

Packet Tracer may not support every MQC, DSCP, queuing, or IOS command available on physical Cisco hardware.

If priority percent 50 or fair-queue is rejected, check the router's supported commands and interface capabilities before selecting an alternative.

The WAN subnet 203.0.113.0/30 provides usable addresses 203.0.113.1 and 203.0.113.2. The external server 203.0.113.10/24 is not directly in that /30 subnet. Configure a separate ISP-side network and appropriate routing, or revise the addressing plan so the server is reachable.

A VLAN provides segmentation, not automatic security isolation. Use ACLs or firewall policies when the business requirement is to restrict communication between VLANs.

QoS prioritizes traffic at configured congestion points; it does not guarantee that tournament traffic will always have a low ping.
